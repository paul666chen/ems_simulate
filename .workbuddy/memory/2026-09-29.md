## 任务：分析"单网卡多IP + 多协议端口与主站连接"的支持范围

### 核心结论（含实测验证）
- **服务端通道的配置 IP 在运行时被忽略**：三条构建路径（device_controller.py:178 / router.py:225 / helpers.py:51）对所有 TCP 服务端强制 `ip=Config.DEFAULT_IP`（0.0.0.0），仅客户端协议使用通道 ip 作为远端目标。
- 实测：配置 127.0.0.1 的 Modbus/IEC104 服务端，netstat 实际绑定 `0.0.0.0:port`；同端口不同 IP 的第二个服务端可创建、可"启动成功"，但 psutil 确认只有 1 个监听套接字，第二个设备连接历史为 0（静默失败假象）。
- 冲突校验（router._server_ip_conflicts）按"不同 IP 不冲突"设计（意图支持同端口多 IP），与运行时 0.0.0.0 绑定现实不一致 → 半成品能力。
- Modbus 服务端 start 是 fire-and-forget（`asyncio.create_task`），绑定失败不报错且 `_is_running=True`；IEC104/c104 绑定失败也静默。
- 协议层差异：IEC104/DLT645/DNP3/IEC61850 的服务端类均支持 ip 参数；ModbusServer 有 setServerAddress 但无调用方。
- 客户端方向：通道 ip = 远端目标地址（多客户端不同远端 IP 可用）；无本地源 IP 绑定能力。
- GOOSE 是唯一按网卡绑定的功能（Npcap，选网卡），与 IP 无关。
- 测试后已删除全部测试通道，端口已释放（DB 恢复空设备状态）。

### 补充实测发现（新证据）
- **P5 生命周期缺陷**：`/api/channels/restart` 对 Modbus/DLT645 服务端返回"重启成功"但无监听（IEC104 正常）；「编辑运行中设备端口」触发自动重载后设备静默停止（15506 → 15507 无监听）。

- 前端未使用 restart/create-and-start 接口；"编辑后自动重载"是 UI 主流程 → P5 用户可见。
